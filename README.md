# RAG Bot — Веб-приложение с диалоговым интерфейсом

Веб-приложение для диалога с RAG-ботом (Retrieval-Augmented Generation). Бот ищет информацию в базе знаний и формирует ответы с помощью языковой модели.

## Описание проекта

**RAG** — технология, объединяющая поиск информации в базе знаний с генерацией текста на основе языковых моделей. Приложение находит релевантные фрагменты в документах и использует их для формирования точных ответов.

### Возможности

- **Диалоговый интерфейс** — веб-чат в браузере
- **RAG-запросы** — поиск и ответы на основе базы знаний
- **Векторный поиск** — семантический поиск через FAISS
- **Индексация документов** — загрузка и переиндексация `.txt` файлов
- **Память разговоров** — контекстные ответы с учётом истории (до 10 сообщений)
- **Два провайдера LLM** — ProxyAPI (основной) и GigaChat (альтернативный)

## Провайдеры LLM

### ProxyAPI (основной)

OpenAI-совместимый HTTP endpoint. Используется по умолчанию (`LLM_PROVIDER=proxy`).

**Преимущества:**
- Работа с OpenAI-совместимыми API
- Полный контроль над HTTP-запросами
- Поддержка GPT-моделей для чата и эмбеддингов

**Модели по умолчанию:**
- Чат: `gpt-4o-mini`
- Эмбеддинги: `text-embedding-3-small`

### GigaChat (альтернативный)

LLM от Сбера. Включается через `LLM_PROVIDER=gigachat`.

**Преимущества:**
- Российский провайдер
- Встроенные эмбеддинги
- Не требует зарубежных API-ключей

**Модели по умолчанию:**
- Чат: `GigaChat`
- Эмбеддинги: `Embeddings`

> **Важно:** у каждого провайдера свой FAISS-индекс (`index_proxy.faiss` / `index_gigachat.faiss`). При смене провайдера выполните индексацию заново.

## Установка и настройка

### Требования

- Python 3.10+
- API-ключ ProxyAPI **или** GigaChat

### Шаг 0: Клонирование репозитория

```bash
git clone https://github.com/BeastHealer/prompt_rag_memory_system.git
cd prompt_rag_memory_system
```

### Шаг 1: Установка зависимостей

```bash
cd web
pip install -r requirements.txt
```

### Шаг 2: Настройка переменных окружения

Скопируйте `example.env` в `.env` (в корне проекта или в `web/`) и заполните значения:

```bash
cp example.env .env
```

**Для ProxyAPI (основной):**

```env
LLM_PROVIDER=proxy
PROXY_API_URL=https://api.proxyapi.ru/openai/v1
PROXY_API_KEY=your_proxy_api_key_here
```

**Для GigaChat (альтернативный):**

```env
LLM_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=your_gigachat_credentials_here
GIGACHAT_VERIFY_SSL_CERTS=false
```

### Шаг 3: Подготовка документов

Добавьте `.txt` файлы в директорию `data/docs/` (кодировка UTF-8).

## Запуск

```bash
cd web
python app.py
```

Откройте в браузере: [http://127.0.0.1:8000](http://127.0.0.1:8000)

### Первый запуск

1. Откройте веб-интерфейс
2. Нажмите **📥** (Индексация) для загрузки документов в базу знаний
3. Начните задавать вопросы в поле ввода

## Технические детали

### Архитектура

```
Пользователь → Веб-интерфейс (FastAPI)
                    ↓
                RAG Pipeline
                    ↓
        ┌───────────┴───────────┐
        ↓                       ↓
   LLM Provider            Retriever
  (ProxyAPI/GigaChat)          ↓
        ↓               VectorStore (FAISS)
   Embeddings + Chat           ↓
        └───────────┬───────────┘
                    ↓
            Ответ пользователю
```

### Компоненты

| Компонент | Описание |
|-----------|----------|
| **providers/** | Абстракция LLM-провайдеров (ProxyAPI, GigaChat) |
| **vectorstore.py** | FAISS индекс + метаданные документов |
| **retriever.py** | Семантический поиск Top-K документов |
| **pipeline.py** | Координация поиска и генерации ответа |

### Настройки RAG

В `config.py` или `.env`:

```env
TOP_K_RESULTS=3          # Количество документов для контекста
MAX_CONTEXT_LENGTH=3000  # Макс. длина контекста (символы)
MAX_HISTORY_LENGTH=10    # Пар сообщений в памяти
```

## Решение проблем

### «База знаний не загружена»

Нажмите **📥** в интерфейсе или выполните `POST /api/ingest`.

### Ошибка API

1. Проверьте ключи в `.env`
2. Нажмите **🔌** для проверки подключения
3. Для GigaChat: установите `GIGACHAT_VERIFY_SSL_CERTS=false` при разработке

### Документы не найдены

1. Убедитесь, что `.txt` файлы лежат в `data/docs/`
2. Проверьте кодировку UTF-8

### Смена провайдера

1. Измените `LLM_PROVIDER` в `.env`
2. Перезапустите приложение
3. Выполните индексацию заново (индексы различаются по размерности эмбеддингов)

## Безопасность

- Не коммитьте `.env` с реальными ключами
- Файл `example.env` содержит только шаблон
- Логи сохраняются в `web/app.log`
