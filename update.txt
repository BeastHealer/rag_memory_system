Обновление RAG Memory System
==============================

Кратко: добавлена система наблюдаемости (журнал взаимодействий в SQLite,
метрики SLA, анализ кэша, экспорт CSV), исправлены ошибки, из‑за которых
приложение не запускалось и логи не экспортировались. README приведён
к текущей логике проекта.


1. Журнал взаимодействий (новое)
--------------------------------
Файл: web/db_logger.py

- Класс DatabaseLogger пишет каждое обращение к чату в data/logs.db.
- Поля записи: timestamp, session_id, query, response, source,
  from_cache, response_time_ms.
- session_id — анонимный UUID (без персональных данных).
- Сбой записи в журнал не ломает ответ пользователю.
- Кэш ответов (data/cache.db) и журнал (data/logs.db) — разные базы.


2. Метрики и API логов (новое)
------------------------------
Файл: web/app.py

- GET /api/logs/stats — сводка:
    total_interactions
    cached_interactions
    unique_sessions
    cache_hit_rate
    avg_response_time_ms
- GET /api/logs/export — скачивание logs.csv (UTF-8 с BOM для Excel).
- POST /api/chat дополнительно возвращает response_time_ms и from_cache.
- Время ответа замеряется вокруг RAG-пайплайна.
- Исключения пайплайна (эмбеддинг, поиск, LLM) ловятся: пользователь
  получает сообщение об ошибке, строка всё равно пишется в журнал.
- Ошибки stats/export отдают HTTP 500 с понятным текстом, а не падают молча.


3. Конфигурация
---------------
Файл: web/config.py

- LOGS_DB_PATH  = <корень>/data/logs.db
- LOGS_CSV_PATH = <корень>/data/logs.csv


4. RAG-пайплайн
---------------
Файлы: web/rag/pipeline.py, web/rag/retriever.py

- Поиск в FAISS выполняется один раз на запрос (раньше эмбеддинг
  вызывался дважды: для контекста и для списка источников).
- Добавлены build_context() и sources_from_results().
- Источники сохраняют порядок появления, без произвольного set().


5. Исправления ошибок
---------------------
- ImportError: LOGS_DB_PATH импортировался в app.py, но не был объявлен
  в config.py — приложение не стартовало.
- NameError: экспорт логов использовал PROJECT_ROOT без импорта.
- При падении retrieve/embed запрос не попадал в журнал.
- CSV без BOM ломал кириллицу в Excel на Windows.


6. .gitignore

  data/cache.db

  data/logs.csv
  *.faiss, metadata_*.json, *.log


7. README.md
------------
Документация переписана под новую логику:
- две SQLite-базы (кэш и журнал);
- эндпоинты /api/logs/stats и /api/logs/export;
- поле response_time_ms в ответе чата;
- схема пайплайна с DatabaseLogger;
- решение проблем: сброс кэша не трогает журнал.


Как проверить логирование
-------------------------
1. Запустить приложение, проиндексировать документы, задать вопрос.
2. Повторить тот же вопрос — from_cache=true, ответ быстрее.
3. curl http://127.0.0.1:8000/api/logs/stats
4. curl -O -J http://127.0.0.1:8000/api/logs/export
